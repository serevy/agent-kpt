# Ledger v0alpha1 fixture

The tests build a synthetic path-quoting problem through this lifecycle:

1. observed in one root lineage;
2. observed in a second root lineage -> recurring;
3. intervention proposed and accepted;
4. intervention applied and verified effective;
5. Keep reinforcing -> habituated -> graduated;
6. model/harness change -> needs revalidation;
7. intervention/problem can be explicitly retired while preserving history.

No real project or session data is used.
